# Code review and fixes

This is the historical review of the initial implementation on 10 November 2026. It covered the frontend, contracts, Go API, database, worker, provider clients, scripts, dependencies, CI, and deployment configuration. See [Verification](VERIFICATION.md) for subsequent checks and [Operations](OPERATIONS.md) for deployment guidance.

The repository had no initial commit. Review used a source snapshot taken before changes, direct source inspection, reproducible failures and regression tests. No commit, push or deployment was performed.

## Results

No P0 issue was found. All 37 confirmed findings below were fixed: 3 P1, 23 P2 and 11 P3. Related symptoms sharing a cause are grouped into a single finding. This records the scope and evidence of this review; it is not a guarantee that no other defects exist.

- P0: immediate critical compromise or widespread irreversible loss.
- P1: a core workflow fails or an ordinary request pattern can seriously affect service availability.
- P2: a reproducible correctness, privacy, accessibility or production reliability defect.
- P3: lower impact validation, feedback, configuration or defensive improvements.

## P1 findings

| ID    | Failure and impact                                                                                                                                                                                | Fix and verification                                                                                                                                                                                                                                                                                                                                      |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1-01 | The installed Tiptap image extension serializes nullable `width` and `height`. API validation rejected these attributes, so inserting an image prevented draft saving and publishing.             | Accept supported nullable, bounded image dimensions. Real editor serialization tests, Go save/publish integration and production HTTP smoke cover the image document. Dia verified rich image paste, autosave and reload.                                                                                                                                 |
| P1-02 | A failed autosave followed by browser Back navigation could lose writing after the editor unmounted. `beforeunload` did not protect client navigation, and an unmount flush could also fail.      | Keep owner/post-scoped recovery in tab storage before saving. Acknowledge only the saved snapshot, preserve newer edits and base revision, and offer explicit recovery/export/discard. Mounted controller and recovery tests cover conflicts. | P1-03 | Each concurrent upload allocated multipart and image buffers before storage quotas. Concurrent authenticated requests could consume substantial memory even when the user was already over quota. | Admit at most four uploads before reading multipart data. Reject overflow with `429` and `Retry-After`; release slots on cancellation and validation failures. Tests verify rejected requests are never read.                                                                                                                                             |

## Validation after fixes

- `bun run check`: source policy, strict TypeScript and Go vet passed.
- `bun run test`: 43 frontend tests with 224 assertions, 5 tooling tests with 24 assertions, and Go unit tests passed.
- `go test -race ./...` with `JOT_TEST_DATABASE_URL` set to an isolated Postgres database: all packages passed, including HTTP/database/worker integration tests. A normal root test without that variable does not exercise database integration.
- `bun run build`: optimized Next.js build and compiled Go API/worker passed together.
- Cross-service smoke against the actual optimized frontend and API passed. Coverage includes real upload bytes, editor image attributes, saved/published documents, compact discovery/history responses, public HTML/profiles, ownership, conflicts, private drafts, ETags, social actions and unpublish.
- Existing preview database upgraded through migrations 2 and 3. Repeating the real migration command succeeded. Database tests also cover schema 1 upgrades, multiple backfill batches and collision rollback.
- Seed script skipped all existing fixtures after the summary-contract change without overwriting posts.
- Dia verified image paste/save/reload, compact publication history, and recovery across an intentional API outage and Back/Forward navigation. The extension disallowed file-chooser upload; real multipart upload is covered by production HTTP smoke, while the browser check used a pasted image referencing that local uploaded asset.
- Formatting, source checks, Compose configuration, frozen dependency install and Bun audit passed.
- Official Go vulnerability scanning found no reachable vulnerabilities. The required-module advisory for `golang.org/x/crypto/openpgp` does not apply to Jot's bcrypt imports. See the [Go advisory](https://vuln.go.dev/ID/GO-2026-5932.json).
- The selector-parser advisory concerns selector parsing of untrusted CSS. Jot uses it for trusted build-time CSS, and the transitive version was patched regardless. See the [maintainer advisory](https://github.com/postcss/postcss-selector-parser/security/advisories/GHSA-rj75-hqrm-r3gf).

## Remaining verification boundaries

This review used controlled provider and storage responses. The Docker daemon was stopped at the time. The [14 November verification](VERIFICATION.md#neon-setup-verification-14-november-2026) records later hosted Neon database and object storage checks, with full container startup covered in the [version refresh](VERIFICATION.md#version-refresh-verification-14-november-2026).

Clipboard fidelity is bounded by the supported editor schema and available image URLs/files. Draft recovery uses local browser storage and depends on the recovery copy being available. Unlisted posts are link-accessible rather than access-controlled. S3 ambiguous-outcome reservations are conservative and can require reconciliation. See `OPERATIONS.md` for deployment, backups, suppression, moderation, perimeter rate limiting and reconciliation responsibilities.
