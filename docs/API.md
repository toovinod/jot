# Jot API contract v1

Go owns `/api/*`; Next proxies these routes without exposing database/provider credentials. All responses are JSON except media/health. Error shape: `{ "error": "human-readable message", "code": "optional_machine_code" }`. Never return raw SQL/provider errors. All private responses use `Cache-Control: no-store`. Unsafe requests require `Origin: APP_ORIGIN` (except the standard email one-click-unsubscribe endpoint, which authenticates with its secret token). When custom domains are on, `POST /api/posts/{id}/view` and `POST /api/authors/{username}/subscribe` also accept `Origin: https://<domain>` (exact host, no port) for a verified custom domain that belongs to the post's author or to that author; every other write still requires `APP_ORIGIN`.

Canonical frontend types and appearance defaults are in `packages/contracts/src/index.ts`. Keep Go JSON property names identical. Public `User` has only `id, username, name, bio, avatar`. No account email/password/session data. Timestamps are RFC3339. Arrays return `[]`, never null. UUIDs are strings. `Post.revision` is an optimistic concurrency version. `Post.published` is an optional Snapshot; public endpoints expose only published values, never draft values. Post counts are `likes`, `comments` and `views` (page reads; the author's own visits are not counted). Snapshots carry `tags` (always an array, `[]` for posts saved before tags existed; at most 5 unique tags matching `^[a-z0-9-]{1,24}$`) and optional `commentsOff` (missing means comments are on). Private full posts include optional `reservedSlug`, the immutable reserved publication slug, optional `scheduledAt` while a scheduled publish is pending, optional `scheduleError` when the worker cleared a schedule (why it gave up; cleared by scheduling or publishing again), and optional `shareToken` while a private draft link is active. Public full posts omit these private fields and the optional duplicate `published` snapshot.

Lists return `PostSummary`, not full documents: `id, author, title, subtitle, slug, cover, visibility, tags, revision, createdAt, updatedAt, publishedAt?, likes, comments, views, excerpt, readingMinutes, isPublished, reservedSlug?, scheduledAt?, scheduleError?, liveVisibility?`. `liveVisibility` is the visibility of the live copy and is absent when the post is not published. Excerpts contain at most 220 Unicode characters and reading time uses 220 words per minute, with a minimum of one minute. Public feed, profile and bookmark summaries use only stored published metadata; owned-library summaries use stored draft metadata. Summaries contain no `content`, `appearance`, or nested `published` snapshot. The optional `reservedSlug`, `scheduledAt` and `scheduleError` appear only in owned-library responses.

## Routes

- `GET /api/health` → `{status:"ok"}` or 503 if DB is unavailable.
- `GET /api/config` → `{aiEnabled:boolean,emailEnabled:boolean,domainTarget:string}`. `domainTarget` is the CNAME host for custom domains, empty when custom domains are off.
- `POST /api/auth/signup` `{email,password,username,name}` → 201 User + session cookie. When email is configured it also queues a verification email.
- `POST /api/auth/login` `{email,password}` → User + session cookie.
- `POST /api/auth/logout` → `{ok:true}`; revoke cookie/session.
- `POST /api/auth/verification/request` → `{ok:true}`; auth. Queues a one-hour verification link (at most 3 per hour); 503 `email_unavailable` without an email provider.
- `POST /api/auth/verification/confirm` `{token}` → `{ok:true}`; single use, 400 `invalid_token` when expired or used.
- `POST /api/auth/password/request` `{email}` → `{ok:true}` whether or not the account exists; queues a one-hour reset link.
- `POST /api/auth/password/reset` `{token,password}` → `{ok:true}`; sets the password, revokes every session and clears the cookie. Rate limited per client.
- `GET /api/me` → User or 401.
- `PATCH /api/me` `{name,bio,avatar}` → User. Username immutable initially. The web client sends `X-Jot-User-ID` with the displayed account ID; a supplied ID that differs from the cookie session returns 409 `identity_changed` before any write.
- `DELETE /api/me` `{password}` → `{ok:true}`; deletes the account and everything it owns in one transaction (posts, editions, comments and replies, likes, bookmarks, views, subscribers, sessions, tokens, jobs, media rows, custom domain), then removes uploaded files best effort and clears the cookie. A wrong password returns 403 `invalid_password`; 5 attempts per 15 minutes. Honors `X-Jot-User-ID` like `PATCH /api/me`.
- `GET /api/me/export` → `application/zip`; one Markdown file per post from its draft (`<slug>.md`, or `untitled-<id>.md`), plus `published/<slug>.md` copies of live posts. Each file starts with front matter: `title, subtitle, slug, tags, status (draft|published), publishedAt?`. 10 exports per hour.
- `GET /api/me/subscribers?offset=0&limit=50` → `SubscriberPage` `{total,items:[{id,email,createdAt}]}`; active confirmed subscribers only, newest first, `limit` up to 500.
- `DELETE /api/me/subscribers/{id}` → `{ok:true}`; removes the address and cancels its queued email.
- `GET /api/me/blocked` → `BlockedReader[]` `[{user:User,blockedAt}]`; auth, the readers the author blocked, newest first.
- `POST /api/me/blocked` `{userId}` → `BlockedReader`; auth. Blocks that reader from commenting on any of the author's posts and hides the reader's comments there, with the replies to them, from engagement and from comment counts. Idempotent: blocking again keeps the first `blockedAt`. 400 `validation` for the author's own ID, 404 for an unknown user. Likes and bookmarks are not affected.
- `DELETE /api/me/blocked/{userId}` → `{ok:true}`; auth, idempotent. The reader can comment again and their hidden comments show again.
- `GET /api/me/domain` → `CustomDomain` `{domain,verified,txtName,txtValue,target}` or `null` when none is set or custom domains are off.
- `PUT /api/me/domain` `{domain}` → `CustomDomain`. The name is trimmed and lowercased; IP addresses, single-label names and the app's own host (and its subdomains) are rejected. Changing the name issues a new TXT value and clears verification. 503 `domains_unavailable` when custom domains are off.
- `DELETE /api/me/domain` → `{ok:true}`.
- `POST /api/me/domain/verify` → `CustomDomain`; looks up TXT `txtName` and verifies when a record equals `txtValue`. 400 `domain_unverified` when not found yet, 409 `domain_taken` when another account already verified the name. Unverified claims never block the real owner.
- `GET /api/domains/resolve?host=` → `{username}` for a verified domain, else 404. Used by the web proxy to map custom hosts to `/@username`.
- `GET /api/domains/allowed?domain=` → 200 for a verified domain, else 404. Used as Caddy's on-demand TLS `ask` endpoint.
- `GET /api/authors/{username}?offset=0&limit=20` → `{author:User,posts:PostSummary[]}`; public posts only, newest first, `limit` up to 50.
- `GET /api/authors/{username}/rss` and `GET /api/rss` → RSS 2.0 (`application/rss+xml`) of the latest 50 public posts, with the full post as escaped HTML in `content:encoded` and tags as `category`. A feed carries at most 2 MiB of post HTML: posts past that budget, newest first, have no `content:encoded` and readers follow their link instead, so every feed fits the cache. Each `description` (the author bio, and each post's subtitle or else its excerpt) is plain text HTML-escaped before XML encoding, so readers that render it as HTML show the text instead of markup. Unlisted posts and drafts never appear. Each API process caches successful feed and sitemap responses for 60 seconds per path, up to 1000 paths and 8 MiB of bodies (a response that does not fit is served uncached), so new posts can take up to a minute to appear. Concurrent misses for one path share a single build.
- `GET /api/sitemap` → `SitemapEntry[]` `[{username,slug,updatedAt}]` for public published posts, at most 50000.
- `GET /api/posts?q=&tag=&sort=latest|popular&limit=20&offset=0` → `{posts:PostSummary[]}`; public feed, bounded pagination. `q` is a case-insensitive substring match on title and subtitle. `tag` keeps posts carrying that tag; an invalid tag returns 400.
- `GET /api/posts?scope=mine|bookmarks` → `{posts:PostSummary[]}`; authenticated, also honors `q` and `tag` (the library uses draft values). Bookmarks only return accessible published posts.
- `POST /api/posts` → 201 Post with empty draft and default appearance.
- `GET /api/posts/{id}` → author-only draft Post.
- `PUT /api/posts/{id}` `{...Snapshot,revision:number}` → saved Post; 409 on stale revision. This route accepts request bodies up to 8 MiB so a document at the content limits fits; every other JSON body is limited to 2 MiB.
- `POST /api/posts/{id}/publish` `{revision:number,emailSubscribers:boolean}` → Post; transactional snapshot + revision + optional delivery jobs. Only public posts may be emailed. Publishing cancels a pending schedule.
- `POST /api/posts/{id}/unpublish` `{revision:number}` → Post. Also cancels a pending schedule.
- `POST /api/posts/{id}/schedule` `{at:RFC3339,emailSubscribers:boolean,revision:number}` → Post with `scheduledAt`. `at` must be 2 minutes to 1 year ahead. The draft is checked as for publishing (title, slug, stable slug, email rules, verified email) but the revision is not bumped. The worker publishes due posts every minute through the same publish code, so the draft as saved at that moment goes live and the optional newsletter is queued then. A publish refused at that moment (for example an emptied title or the newsletter budget) clears the schedule instead of retrying and records the refusal message as `scheduleError`. Any other failure is retried on the next passes without holding up later posts; after 5 failed passes the schedule is cleared with a `scheduleError`. Scheduling or publishing clears `scheduleError`.
- `DELETE /api/posts/{id}/schedule` → Post without `scheduledAt`.
- `POST /api/posts/{id}/share` → `{token}`; a private read-only draft link token (32 random bytes, base64url). Calling it again rotates the token and the old link stops working. The owner's Post includes `shareToken` while active.
- `DELETE /api/posts/{id}/share` → `{ok:true}`; revokes the link.
- `GET /api/shared/{token}` → `SharedDraft` (the current draft Snapshot plus `author` and `updatedAt`), no auth, `X-Robots-Tag: noindex`, never cached. 404 for unknown or revoked tokens.
- `DELETE /api/posts/{id}` → `{ok:true}`; author-only.
- `GET /api/posts/{id}/revisions` → `{revisions:RevisionSummary[]}`; author-only, newest first, at most 100 entries containing `id, number, title, createdAt`. `number` counts the post's editions from 1, oldest first. Restoration loads the full historical snapshot on the server.
- `POST /api/posts/{id}/restore` `{revision:number,versionId:number}` → Post; restore snapshot into draft without changing live publication.
- `GET /api/public/{username}/{slug}` → published Post or 404, including unlisted links; no draft leakage.
- `POST /api/uploads` multipart field `file` → 201 `{url:string}`; auth, signature/size validation; PNG, JPEG, GIF or WebP up to 10 MiB and 40 megapixels. At most four uploads per API process may decode/buffer concurrently; excess requests return 429 before their multipart body is read. Durable author limits are 20 uploads and 50 MiB per hour, 256 MiB total, and 2000 assets. If the account is deleted while the image is being stored, the stored image is removed and the upload returns 409 `account_deleted`.
- `GET /media/{key}` → immutable uploaded image for local-disk mode. Uploaded images are public assets with unguessable names; drafts themselves stay private.
- `GET /api/posts/{id}/engagement` → `Engagement` `{liked:boolean,bookmarked:boolean,likes:number,comments:Comment[],commentsOff:boolean}`; published posts only, optional session. Comments are the newest 100 top-level comments, newest first, followed by up to 50 newest replies for each of them; a reply has `parentId`. Comments by readers the post's author blocked, and replies to them, are left out (and are not counted in `comments`).
- `POST /api/posts/{id}/view` → 204; no auth. Counts one read per viewer per post per day (viewer is the signed-in user, otherwise the client address, with IPv6 collapsed to its /64, as an HMAC-SHA256 keyed by `VIEW_HASH_SECRET`, or a per-process random secret when it is empty, and the UTC day; the user agent is not used). Ignores the author and unpublished posts; 30 per minute per client address.
- `PUT /api/posts/{id}/like` `{active:boolean}` → `{ok:true}`; auth, idempotent.
- `PUT /api/posts/{id}/bookmark` `{active:boolean}` → `{ok:true}`; auth, idempotent.
- `POST /api/posts/{id}/comments` `{body:string,parentId?:string}` → 201 Comment; auth, plain text, length bound. Replies are one level deep: `parentId` must be a top-level comment on the same post, else 400 `invalid_parent`. 403 `comments_off` when the live copy has `commentsOff`; 403 `blocked` when the post's author blocked the signed-in reader.
- `DELETE /api/posts/{id}/comments/{commentId}` → `{ok:true}`; comment owner or post author. Deleting a comment deletes its replies.
- `POST /api/ai/jobs` `{postId:string,mode:"grammar"|"structure"|"review",text:string}` → 202 `{id:string}`; owned post, configured provider, 1–120,000 bytes of UTF-8 text and 10 suggestion jobs per author per hour. Suggestion modes reject `prompt`, `context`, `title`, `subtitle`, `scope` and `history` unless they are absent or empty.
- `POST /api/ai/jobs` `AIChatRequest` `{postId,mode:"chat",prompt,context,text,title,subtitle,scope:"page"|"selection",history:AIChatTurn[]}` → 202 `{id:string}`; a conversation with jot ai from the editor's prompt box. `prompt` is 1–4,000 bytes and not blank; `context` (source material the writer attached, `""` when none) is 0–60,000 bytes; `text` (the page or the selection, as Markdown) is 0–120,000 bytes, so an empty page can ask for a new post; `title` and `subtitle` are the page's current ones, at most 200 and 500 characters as when saving a post; `history` holds at most 12 earlier turns `{role:"user"|"assistant",content}` of 1–8,000 bytes each. No field may contain NUL. Limits are bytes unless stated and match `aiChatLimits`. Violations return 400 `validation` with a message naming the field (for example `History turn 3 is longer than 8,000 bytes`). Chats have their own budget of 40 per author per hour, separate from the 10 suggestions; a full budget returns 429 `rate_limit` saying when to try again (`Chat limit reached (40 messages an hour); try again in about 12 minutes`).
- `GET /api/ai/jobs/{id}` → `{id,status:"pending"|"running"|"completed"|"failed",result?:string,error?:string}`; owning user only. A completed chat's `result` is a JSON-encoded `AIChatResult` `{reply:string,edit:string|null,title:string|null,subtitle:string|null}`: `edit` is the full Markdown replacement for exactly the request's `text` (only the selection for `scope:"selection"`), or null when jot ai only replies; `title` and `subtitle` are single-line replacements (at most 200 and 500 characters) or null to keep the current ones, and are always null for a selection. The provider answers with strict structured output and `store:false`; an incomplete, refused or unusable answer fails the job with a readable `error`.
- `POST /api/authors/{username}/subscribe` `{email:string}` → `{ok:true}`; generic response whether existing/new; enqueue confirmation if configured.
- `POST /api/subscriptions/confirm` `{token:string}` → `{ok:true}`; idempotent confirmation, expiring token.
- `POST /api/subscriptions/unsubscribe` `{token:string}` → `{ok:true}`; idempotent, cancel queued newsletters.
- `POST /api/subscriptions/one-click?token=...` → `{ok:true}`; RFC8058 form request, token-authenticated, no cookie/origin requirement.

## Web routes

`/` public discovery/landing, `/login`, `/signup`, `/dashboard`, `/editor/[id]`, `/settings`, `/[handle]` for `@username`, `/[handle]/[slug]`, `/share/[token]`, `/subscriptions/confirm?token=...`, `/subscriptions/unsubscribe?token=...`, `/auth/verify?token=...`, `/auth/reset?token=...`. Confirmation/unsubscribe pages require a user action rather than mutating state on a GET.

## Content and UX rules

Document type is a Tiptap/ProseMirror JSON document. Supported nodes: doc, paragraph, text, heading (1–6), bulletList, orderedList, listItem, blockquote, codeBlock, hardBreak, horizontalRule, image, table, tableRow, tableCell, tableHeader, taskList, taskItem. Supported marks: bold, italic, strike, code, underline, link. A document holds at most 50,000 nodes, 500,000 bytes of UTF-8 text and 32 levels of nesting. Sanitize/validate URLs and node bounds server-side and render with React nodes, not raw HTML. Appearance layout is a permutation of header, cover, content, author.

AI content is a suggestion. Show the original/requested text and resulting suggestion. A chat `edit`, `title` or `subtitle` is also a proposal: the writer applies it explicitly, and the editor must not apply it to a page or selection that changed after the request. Copying suggestions is supported; accepting must be explicit and must not silently remove images or apply to a changed document. Review mode flags possible gaps, does not assert source-verified corrections.

Search (`q`) is a case-insensitive substring match on title and subtitle, not full-text search: published values for public lists, draft values for the author's library, using parameterized SQL. Authenticated drafts, engagement state and AI status are never shared-cacheable. Public ETags must follow visibility checks; unpublish and deletion cannot be bypassed by a cached response.

## Validation and operations

Image document attributes may contain nullable `width` and `height`, or integer pixel dimensions from 1 to 12000 (numeric strings from pasted HTML are accepted). Persisted text rejects actual NUL characters with 400; literal code examples containing the characters `\u0000` remain valid.

Deleting a post cancels and redacts associated AI work transactionally, including completed source/result copies and chat prompts, context and history; only the post ID and mode remain, so redacted chats keep counting against the chat budget. Enqueue locks the owned post until its transaction commits, so concurrent deletion cannot miss new work. A request already sent to an external provider cannot be recalled. Switching a publication to unlisted also cancels previously queued newsletter work.

Newsletters and feeds render the post with the shared Go renderer (`domain.RenderHTML`, `domain.RenderMarkdown`): all text is escaped, only safe link and image URLs are emitted, `/media/` paths become absolute `APP_ORIGIN` URLs and code blocks keep their `language`. Each newsletter contains the exact published edition it was queued for. The persisted email request is bounded at 4 MiB, which fits HTML plus text for any post at the 500,000-byte text limit; a post whose links or markup still push it past the bound sends the subtitle and link instead, logs a warning and records `contentOmitted` in the job payload and result. The newsletter sender is `"<author name> via <instance>" <EMAIL_FROM address>`, where the instance is the display name in `EMAIL_FROM` (or `jot`) and the author name is stripped of control characters, quotes and angle brackets and cut to 64 characters; confirmation and account emails keep `EMAIL_FROM` as is.

Run the migration command before restarting the API and worker. Version 002 reserves publication slugs even while posts are unpublished. For legacy posts it preserves the current published slug, or the latest historical published slug when unpublished; older historical URLs never displace a current publication. New posts reserve their slug on first publication. A legacy historical collision stops the migration without changing URLs; back up/export the affected posts and explicitly resolve the duplicate as described by the migration error before retrying. Version 003 backfills bounded list metadata from each draft and publication using the same summary function used by normal saves and publishing. Version 004 adds scheduling, share tokens, view counts (`post_views` keeps one row per viewer per post per day and is pruned after two days), comment replies and custom domains; it needs no backfill because summaries without `tags` read as `[]`. Version 005 adds `posts.schedule_attempts` and `posts.schedule_error` for scheduled-publish failures. All migration versions and backfills commit in one transaction; rerunning is idempotent.

`APP_ENV` accepts `development`, `test`, or `production`; an unset value uses development behavior. Production requires an HTTPS `APP_ORIGIN`. S3 mode requires its bucket, access key, secret key and public URL together. Public image base URLs must be absolute HTTP(S) URLs without credentials, query or fragment, and must use HTTPS when the application does.

If an S3 write attempt fails after transmission, its outcome may be unknown. Its `media_assets` reservation stays charged against storage and hourly limits. Administrators should compare the recorded key against object storage before resolving a reservation; no automatic process deletes objects based solely on a failed response. A local file failure releases its reservation only when no file was created or removal succeeded.
